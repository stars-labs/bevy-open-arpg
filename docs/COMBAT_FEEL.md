# 战斗手感：响应、节奏、反馈与容错

状态：2026-11-05 本轮实现与验收完成。目标是在真实攻击循环中建立清晰因果，不靠堆特效掩盖输入迟滞。右键移动、左键攻击，Q/E/R与Shift保留原输入职责。本文取代旧的全局卡刀方案。

## 验收要求

| 项目 | 当前实现 | 必须检查的行为 |
|---|---|---|
| 输入响应 | 普攻/技能/闪避短输入缓存，显式技能优先；收招窗口允许衔接和移动 | 早按不轻易吞输入，过期不自动施放，UI/暂停不泄漏指令 |
| 攻击节奏 | 普攻更早接触、紧凑起手与快速挥刃；重击更长蓄势与更强接触；出手期间朝向保持、允许平移，收招可转向，闪避可打断 | 起手、挥击、接触、收招可辨；刀刃领先，脚底稳定，确认命中不倒放 |
| 局部卡刀 | 仅接触双方动作短暂停顿，保持—拖刀—释放；分段积分适配长帧 | 世界计时、其它敌人和投射物不减速；召唤物命中不暂停主人 |
| 命中因果 | 成功接触才有受击、接触音和震动；挥空仅轻剑风及原动作 | 空挥和空技能不伪造命中；暴击、重击、击杀、破防有不同强度 |
| 视觉克制 | 每目标一层主要接触效果，已有击退/挤压；远程维持施法与元素语言 | 多目标不叠震屏，不全屏闪白，不让技能光效遮住目标轮廓 |
| 听觉层次 | 剑风/接触分离，金属/骨质/肉体区别，确定性轻微变调和音量变化 | 技能伤害不重复播放通用命中音；同帧最多一条主要语义提示和一层接触 |
| 闪避与中断 | 站立也按当前意图闪步，方向稳定，短无敌与冷却，按帧内有效时长积分 | 不穿封闭边界，闪避取消未释放伤害；已经飞出的箭不凭空消失 |
| 状态清理 | 菜单/暂停清缓存，读档清未释放攻击、在途效果与局部停顿 | 不在恢复菜单后误出招，不把旧镜头偏移、追击或标记留在新状态 |

参数集中在 `assets/data/combat_feel.ron`。普通命中基础停顿35ms，暴击55ms，重击约70ms，破防85ms；根据冲击与敌人等级有限调整。普攻接触约在周期36%，恢复取消60%，续击68%；角色移动/转向、技能冷却与世界时间不随局部暂停缩放。

八种表现手段按作用选择：停顿用于接触、震屏用于真实冲击、碎屑用于材质、挤压用于受击、短轨迹用于运动方向、音高变化减少机械重复。这里不添加常驻满屏闪白或全局慢镜；召唤物数量多时尤其不能拖慢玩家控制。

## 实现边界

- `src/combat/feel.rs`：配置及输入/范围/清理契约。
- `src/combat.rs`：真实接触、输入优先级、伤害与声音触发；开发录制的必暴击仅在显式dev fixture内覆盖，正式暴击上限不变。
- `src/player.rs`：分阶段姿态、局部动画时钟、恢复衔接、定向闪步。
- `src/feedback.rs`：局部暂停精确积分、相机偏移恢复、音频分类与限流。
- `src/combat/presentation.rs`：接触素材和目标材质，暴击/击杀强度。
- `src/enemy.rs`、`src/combat/summons.rs`：受击者和召唤物自己的动作时钟。
- `src/save.rs`：读档后清除瞬时战斗状态。

## 浏览器验收（2026-11-13）

对象是 `bash scripts/build_web.sh` 生成的发布包（build id `650dfec4ca379a67`），本地 HTTP 服务，Google Chrome 156 无头模式，由 Playwright 发送真实键鼠事件。脚本、截图、录像与控制台记录在 `target/validation/web-acceptance/`（`harness/accept.sh` 可重跑）。

| 项目 | 结果 |
| --- | --- |
| WebGPU 适配器 | AMD（`--enable-unsafe-webgpu --enable-features=Vulkan --use-angle=vulkan --use-webgpu-power-preference=force-low-power`）通过。NVIDIA RTX 3070 适配器在本机无头 Chrome 中 `VK_ERROR_OUT_OF_DEVICE_MEMORY` / DeviceLost；一个只清屏的最小 WebGPU 页面同样丢失设备，因此是本机 Chrome/Dawn 与 NVIDIA 的环境问题，不是游戏内存占用（游戏到失败时只申请了约157MB纹理与缓冲）。仅 `--enable-unsafe-webgpu` 得到 SwiftShader 软件适配器，未用于验收 |
| 加载与进入 | 主菜单约8秒出现；回车进入职业选择，再回车进入第一章。1280×720 下菜单、职业选择、HUD 均正常渲染 |
| 灰誓卫士近战 | 右键移动接近敌人，左键连击：出现目标锁定圈与刀光，敌人倒地，目标计数 0/3→1/3，怒气 60→78，拾取战利品日志出现。Shift 闪避显示“闪避”并进入冷却 |
| 烬语者 | R 技能在落点出现符文，魔能 120→84 并进入冷却 |
| 控制台 | 三次最终运行均为0条 error / pageerror / panic。修复前每次加载有153条 `.meta` 404（见下） |
| 音频 | `AudioContext` 状态为 `running`；无头环境无法试听，接触音与剑风未在浏览器中逐条确认 |

本轮修复的仅 Web 问题：Bevy 在 HTTP 下为每个资源先探测 `<资源>.meta`，仓库不提供这些文件，导致每次加载153条404控制台错误。wasm 构建现在设置 `AssetMetaCheck::Never`。

**没有在浏览器中验证的内容**：卡刀、拖刀与震屏的毫秒级时序（25fps 录屏与截图只能确认命中、刀光、击杀和资源变化，精度仍由原生系统测试与原生实捕支持）；暴击/重击/破防的强度差异；Q/E 技能（1级未解锁）与需要目标的 R 裂地斩命中；烬语者普攻火球在本次脚本中没有拍到弹体；骨弦游猎与缚魂使；移动端。844×390 视口下右侧工具栏与小地图、罗盘重叠，HUD 目前只适配桌面尺寸。

伤害与原生实捕一致（22 / 38.5 / 29.52）。四档卡刀时长与 `combat_feel.ron` 的 35/55/70/85ms 档位对应，强度顺序为普攻 < 暴击 < 重击 < 破防。

**音频**：`AudioContext` 为 `running`；在所有接到扬声器的节点前插入分析器采样输出电平。接触音入队后 350ms 内峰值相对之前 1.5s 的环境底噪（约 0.146–0.149）上升：普攻 0.222、暴击 0.290、重击 0.559；暴击与重击的剑风为 0.188 / 0.208，普攻剑风（0.1495）与底噪无法区分。每场 `AudioBufferSourceNode.start` 调用 319–346 次。这证明接触音确实进入输出且强度有层次，不是主观试听。

**仍未在浏览器中验证**：无头 Chrome 在本机只有 5–13fps（640×360、关闭录像后仍是 10–13fps），一帧 75–200ms，长于任何一档卡刀，因此逐帧采样的动画缩放从未低于 1，**卡刀与拖刀的逐帧时序在浏览器里没有独立测到**，上表是事件载荷而非帧测量；相机偏移的帧测量混入了镜头跟随，不作为震屏幅度证据。毫秒级积分仍由原生系统测试和原生实捕支持。烬语者普攻火球本身没有产生接触事件记录（表中接触来自 E），原生 `feel-ranged-hit` 为 17 伤害。真实浏览器帧率是否也这么低未知，需在有显示器的机器上确认。

### 移动端 HUD

`HudViewport`（桌面 / 横屏 / 竖屏）是所有 HUD 布局分支读取的唯一判定。横屏（如 844×390）把导航栏挂在小地图正下方、罗盘移到小地图左侧；竖屏（如 390×844）把两个资源球叠到技能栏上方，技能格保持 ≥44px，道具格放大到 ≥46px。技能格与道具格点击/轻触会按下对应按键，并撤回这次左键，不会同时打出普攻（原生实测：点击 E 格造成 28 伤害、怒气 100→55，无额外普攻）。技能格不是 `Button`，光标停在技能栏上不会触发 `UiPointerCapture` 吞掉 Q/E/R。需要目标的技能（如卫士 R）仍按光标取目标，点技能格时光标不在敌人身上，所以不会释放；触屏下这类技能还需要自动取敌。**没有实现触屏移动与普攻**（世界内点击仍只读鼠标），所以手机上目前只有 HUD 可用，整局不可玩。截图见 `target/r2/shots/review.png`。
